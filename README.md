# Практическая работа №6. Структурирование приложений FastAPI

Планировщик событий находится в папке `planner`.
Предыдущие файлы приложения с задачами и шаблонами сохранены.

## Запуск

Из корня проекта создайте и активируйте виртуальное окружение:

```bash
python -m venv venv
```

Windows PowerShell: `.\venv\Scripts\Activate.ps1`.
Linux/macOS: `source venv/bin/activate`.

Установите зависимости и запустите планировщик:

```bash
python -m pip install -r requirements.txt
cd planner
python main.py
```

Откройте http://127.0.0.1:8080/docs.

## Структура планировщика

- `main.py` — приложение и подключение маршрутизаторов.
- `models/events.py` — модель события.
- `models/users.py` — модели пользователя, регистрации и входа.
- `routes/events.py` — просмотр, создание и удаление событий.
- `routes/users.py` — регистрация и вход.
- `database/connection.py` — пустой файл для следующей работы с базой данных.

## Проверка через Swagger

1. GET `/event/` — пустой список.
2. POST `/user/signup` — регистрация по примеру в Swagger.
3. Повторная регистрация — ошибка 409.
4. POST `/user/signin` — успешный вход; неверный пароль — 403;
   незарегистрированный email — 404.
5. POST `/event/new` — добавление события с ID 1.
6. GET `/event/` и GET `/event/1` — просмотр добавленного события.
7. DELETE `/event/1` — удаление. Повторное удаление — 404.
8. Добавить несколько событий с разными ID и выполнить DELETE `/event/`.

В папке `docs` находятся use case диаграмма для draw.io и основные сценарии.

Как в примерах методички, данные хранятся в памяти и теряются после перезапуска.
Вход только проверяет email и пароль: токены и ограничения доступа в этой работе
не реализуются. Пароли хранятся в открытом виде в учебном словаре.
Обновление событий отложено до работы с базой данных согласно методичке.
Исправлены опечатки в импортах и проверке пользователя. Примеры моделей
записаны для Pydantic 2. В `User` нет пароля, `NewUser` добавляет его для регистрации.
Добавлена проверка повторного ID события, чтобы идентификаторы были уникальными.

Прежнее приложение запускается из корня проекта командой
`python -m uvicorn api:app --reload`, адрес http://127.0.0.1:8000/todo.
